# Personal travel claims table

Open **My travel claims → Claims table**. Search reference/activity text, choose a claim type or filing status, filter recorded activity end dates, and choose an order. Every selection applies to all matching records; pages contain at most 30 filings. Links open the existing filing and its checklist. Even administrators see only their own filings in this view. The separate review and verification queues keep their current purpose.

The standard server-rendered table is the default. **Open interactive table** uses the already vendored MIT Tabulator 6.7.1 for resizable columns, horizontal scrolling and remote paging. Filtering and sorting use native GET controls above the table, so keyboard, mobile and no-JavaScript users can perform the same selection. No new dependency or service is installed.

Dates are the **recorded filing snapshot**. The existing filing page may refresh linked activity dates and deadlines under its existing rules; this new view never refreshes or writes them. Open the filing for its current deadline, checklist, flag reviews and next step. No inferred overdue state is shown. **Submitted** means handover recorded, without asserting approval or payment. Financial amounts, answers, document links and flag details are excluded from this list.

The native table and page links remain usable without JavaScript or if the vendor bundle is blocked. On interactive request failure, the original standard page returns with an explicit explanation; **Reload this selection as a standard table** opens the requested page. This avoids presenting an old standard page as the failed requested page. Printing uses the native original selection/page. The table does not claim to print every page.

`GET /travel/table` serves HTML; `format=json` serves the same bounded snapshot. Each request validates the registered session against current active account state and requires Travel filing to be enabled. Owner scope is always server selected. Parameter values cannot select another owner, columns or arbitrary SQL. Search is literal Unicode casefold reference/activity matching, including percent/underscore characters. Date/filter/order/page validation errors return no records. Count and rows share one SQLite read transaction; stable ID ordering breaks ties. Requests above the last current page clamp to it. Responses and local errors use `Cache-Control: no-store`.

All browser labels are plain text. Filing destinations are locally constructed and path encoded. The optional grid makes no outside requests, business writes or notifications. Existing Tabulator integrity/advisory gates cover the reused bundle. `travel_grid.py` is included in the deployment runtime closure. No schema, approval, calculation, existing claims dashboard or review-queue behavior is changed.

Tests cover owner/admin separation, switch/session revocation, field minimization, all-page sort/filter/paging, Unicode/literal/markup search, invalid selections, unchanged filing snapshots, and authenticated Chromium journeys in light/dark/contrast at phone/desktop widths. Browser journeys cover actual remote paging, native filter submission, record links, safe long labels, blocked scripts, no-JavaScript fallback, failed requests and retry. All fixtures are synthetic; these checks do not establish real claim approval or provider delivery.

## Current-selection CSV export

Choose **Export current selection (CSV)** in either standard or interactive mode. The native download also works without JavaScript. It contains all matching pages in the currently applied sort order and the same six table columns. Current page and column widths do not restrict the export. Edited controls take effect only after **Apply selection**; browser paging does not change the selection or order.

Each download reads a fresh owner-filtered snapshot under the same current registered-session/account and Travel feature checks. Changes since the page was loaded are reflected in the download. Administrators still receive only their own filings. Search is literal Unicode casefold matching; date/status/type/order validation is shared with the table. Answers, financial amounts, document links, flag details and other owners remain excluded. Dates remain recorded snapshots. There is no deadline refresh, business write, schema/dependency change or notification.

The CSV uses UTF-8 with a BOM for spreadsheet compatibility, conventional quoting for commas/quotes/newlines and English column/status/type labels matching the table. Potential spreadsheet formula prefixes (=, +, -, @ after leading whitespace, or initial tab/CR/LF) receive an apostrophe. Empty results produce a header-only CSV. The fixed filename is `travel-claims.csv`; `X-Export-Rows` reports the record count. Success and local error responses use no-store.

Selections above **10,000 matching filings** return an accessible HTML error with a return-to-selection link and no attachment or partial file. The bound applies after ownership and filters. Narrow the selection and retry. Exports are built from a single bounded SQLite statement, sharing the same predicates and deterministic ID tie-breaker as table pagination. No hidden or arbitrary query-selected columns are exported.

Actual authenticated Chromium downloads cover phone/desktop light/dark/contrast, native/interactive page-two selections, unapplied controls, no JavaScript and usable refusal recovery.

## Private saved selections

Expand **My saved claims views**. Give the applied selection a name and choose **Save current selection**. Each account can keep up to ten views. The saved state contains search, claim type, filing status, recorded end-date bounds, sort field and direction. Edited filter controls require **Apply selection** first. Column widths, page number, record contents, other-owner scopes and credentials are not stored.

Choose **Open saved view** to start at page one with that selection. The existing table, native page links, optional interactive table and CSV export reuse current authorization and selection rules. Additional filter/page query parameters on a saved-view link cannot alter the stored selection. After opening, ordinary native pagination and export use the expanded filters and order. The table and export always show the current matching owner records, rather than a frozen saved result.

**Replace saved selection** stores the currently applied table filters/order and the displayed name; edit the name there to rename and replace together. **Delete saved view** removes only that preference. Both operations carry the revision rendered on the page; if another tab changed or deleted the view, the request is refused without overwriting current state. Reload the table and review the current view before retrying. Duplicate names use Unicode casefold within the account; another account can use the same name. Replacements remain available at the ten-view limit.

All controls are native forms/links and work without JavaScript across signed-in devices. Native same-origin POSTs use the application's shared exact-origin protection, with a standalone route check, an 8KiB body bound and strict form/state validation. Session/account and Travel switch are rechecked inside the serialized preference transaction. View IDs/revisions never select another owner. Errors and successful redirects are no-store. Failed writes roll back; concurrent updates cannot silently win, and concurrent creates cannot bypass the limit.

The additive `travel_claim_view` table contains only owner ID, name/casefold key, validated schema-1 selection and revision, with an account foreign key and cascade delete. Listing preferences does not parse their saved JSON: an invalid stored selection can still be replaced or deleted from the ordinary table page, while opening it returns a safe error. Claims, checklists, deadlines, notification records, approval and payment state are unchanged. No external provider or dependency is added.
