# Document experience: My desk and workspace

Candidate 10.05, November 7, 2026. Implementation branch:
`feat/documents-my-desk`. This is the first navigation/workspace increment of
the requested friction reduction, not the entire intake redesign.

## Current behavior

- The application's Documents entry opens My desk (`/documents/actions`). Existing
  `/documents` URLs remain the register, preserving bookmarks, exports and saved views.
- Primary navigation contains My desk, permitted Inbox, Register and Overview,
  plus Settings for existing workflow administrators. My desk retains next-step
  and division views and adds direct links to mentions and permitted Director routing.
- A single register form combines queue selection and search. Existing queue,
  search, pagination, saved-view, export and authorization services remain in use.
- Detail pages summarize status, lead and deadline and link to next action, source,
  requests/work, files and history. Requests, assignment controls and shared-work
  links now appear together; repeated assignment summaries and draft-link forms
  are removed. Full source interpretation remains expandable.
- Desktop shows next-step guidance and its action beside the source. Phones place
  actions first. JavaScript moves the existing authorized primary details/form
  into that panel and expands it, retaining the original form action, revision,
  CSRF and input nodes. It does not clone forms, submit actions or call providers.
- Without JavaScript, the existing action remains in additional actions. Existing
  links, native disclosure controls and all server-side authorization still work.
  Supporting-section links expand their ancestor disclosures when scripts run.

No schema, dependency, permission, workflow transition, integration or release
policy change. No production data, remote relay or notification operation.

Full normal/shuffled CI and release gates remain required before deployment.
