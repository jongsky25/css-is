## Candidate fix and remaining warning

`storage.audit` now converts target IDs before hashing and obtains a writer
reservation with `BEGIN IMMEDIATE` before reading the tail when no transaction
is active. Caller-owned write transactions and `commit=False` retain their
existing commit/rollback ownership. SQLite's existing busy timeout still applies;
an existing deferred read transaction that cannot upgrade fails rather than
silently appending a fork. No historical hashes or verifier rules change.

New regression coverage exercises numeric-zero IDs, simultaneous independent
writers, caller rollback/commit and continued detection of old corruption.

This prevents the reproduced write defects after deployment. It does **not**
clear the live historical warning. Rehashing old records would conceal the
original discrepancies. A separately designed, explicitly approved historical
incident acknowledgment/checkpoint would be needed to distinguish an accepted
historical incident from new failures without discarding this evidence.
No live database mutation, restart, merge or production deployment is included.
